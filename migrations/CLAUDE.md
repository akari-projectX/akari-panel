# akari-panel/migrations

sqlx 迁移，经 `db::migrate`（先校验 PostgreSQL ≥ 18）在 `serve`、`server add`、`admin add` 启动时自动执行。

- **基线**：整个 schema 是 **`0001_baseline.sql`**（由已迁移库的 `pg_dump` 生成，按领域分节：类型、函数、按组的表（含各自的约束、索引、触发器）、外键、种子行；SQL 函数在表之前创建，所以文件用 `SET LOCAL check_function_bodies = false`）。**没有版本守卫**：这是一个新项目，库只能从空库建起。基线**不写 `public.`、不改 search_path**（testdb 每个测试在自己的 schema 里迁移）。月分区 `traffic_daily_YYYYMM` 由基线末尾的 `akari_ensure_traffic_partitions(1, 2)` 与 reaper 创建，不写死在文件里。
- **编号**：`NNNN_<topic>.sql`，下一个编号 = 最后一个 + 1（基线之后的第一个是 `0002`）。并行分支撞号时由后合并的一方重新编号。
- **只追加，不修改**已合并的迁移文件（sqlx 会校验 checksum，改了已部署环境会拒绝启动）。
- 改列名/加列后，同步检查 `src/` 中所有手写 SQL 与 `FromRow` 结构体（没有编译期 SQL 校验）。
- 分区表让 `pg_restore --clean` 失败（删不掉分区继承的约束）：恢复一律进**空库**（安装器 `restore_into` 先 `DROP DATABASE … WITH (FORCE)` 再建，`restore.sh`/`restore-drill.sh` 不再用 `--clean`）。
