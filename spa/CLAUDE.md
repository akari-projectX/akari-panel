# akari-panel/spa — 前端

React 19 + Vite 8 (Rolldown) + Tailwind 4 + TanStack Query 5；shadcn 风格组件为手拷代码（`src/components/ui/`）。
**两个独立打包（R23，推翻 M3 的单 SPA）**：用户门户（`index.html` → `src/main.tsx` → `src/app.tsx`，产物 `dist/app`，在 `/{prefix}/app`）与管理后台（`admin.html` → `src/admin-main.tsx` → `src/admin-app.tsx`，产物 `dist/admin`，在 `/{prefix}/admin`，仅对管理员会话下发）。`npm run build` = tsc + 两次 `vite build`（第二次 `AKARI_BUNDLE=admin`）+ `scripts/check-bundles.mjs`。共用的 `src/mount.tsx`（QueryClient + 挂载）、`lib/`、`components/`、`i18n/` 两边各自打包（不共享 chunk）。产物被 rust-embed 编进二进制。改完前端必须 `make spa && make panel` 才生效。

**门户不得引用后台代码**：`src/main.tsx`/`src/app.tsx` 及其依赖不得 import `src/admin-*`、`src/pages/admin-*`、`src/pages/audit.tsx`（门户构建的 `userBundleGuard` 直接报错）；后台专用文案、API 路径、错误映射（`lib/admin-errors.ts` 的 `ADMIN_CODES`，W21；`src/lib/admin-*` 同样在门户构建守卫里）只能出现在后台模块或只被后台调用的导出里（单模块内未用的导出会被 tree-shake）。`check-bundles.mjs` 的标记（后台 API 路径如 `/users`、`/nodes`、`/rollouts`，以及"管理后台""审计日志"等）必须同时出现在后台产物中（防失效）；新增后台视图/接口时补标记。门户只知道 `/admin` 这一个跳转目标（`adminBase`）。

## 结构

- **W26 协议表单**：`src/lib/admin-protocols.gen.ts` 由 `proto/protocols.toml` 生成（`make gen-protocols`，`cargo test`/`make check-generated` 在过期时失败；prettier 忽略此文件），`src/lib/admin-protocol-form.ts` 读取它：自选传输模板（`transport`）的协议、各协议可用传输（带各订阅格式不支持的说明）、需 TLS（协议 `template_requires_tls` 或模板规则）、传输字段（中文标签/帮助/取值）、L4；常用模板（REALITY、Vision、SS2022…）在 `admin-nodes.tsx` 里是按模板的 UI 覆写，但其取值（指纹、XHTTP 模式、SS 方法）同样来自清单。测试 `lib/admin-protocol-form.test.ts`、`admin-nodes.test.tsx`。
- `src/lib/api.ts` — fetch 封装与 API 类型（手工镜像 `src/api.rs` 的 View 结构，改后端字段要同步）。`appBase`/`apiBase` 从 `location` 推导，**不内嵌前缀**。
- `src/lib/router.ts` — 极简 history 路由（`usePath`/`navigate`），无路由依赖；`loadPage(url)` = 整页跳转（门户 ↔ 后台是不同的包；测试里 `vi.mock` 它）。前缀 = 路径第一段（`prefixBase`），`appBase` = `/{prefix}/app`、`adminBase` = `/{prefix}/admin`。后台视图即 URL：`/{prefix}/admin/{users|plans|orders|nodes|updates|audit|account|…}`（`admin-app.tsx` 的 `VIEWS`/`viewOf`；深链与后退可用）。门户：`/me` 为管理员或 enroll 阶段 → `loadPage(adminTarget(path))`（`/app/nodes` → `/admin/nodes`，所以登录前打开的视图保留）；后台：会话结束 → `loadPage(loginTarget(path))`（`/admin/nodes` → `/app/nodes`），非管理员 → `/app`，登出 → `/app`。**`/{prefix}/app/`、`/{prefix}/admin/`（带尾斜杠）不是路由**（面板返回拒绝 404），导航一律用 `appBase`/`adminBase` 或 `base + "/<view>"`。
- `src/lib/errors.ts` — **按错误码映射（W21，M6）**：服务端错误体带 `code` + `params`（`ApiError.code`/`.params`）。`errorText(err, t)`：门户能遇到的码（命名空间 auth/account/signup/shop/order/coupon/balance/withdrawal/invite/ticket/request）经 `CODE_KEYS` 映射到 i18n `errors.*`（中英双语，`{参数}` 插值，`<p>_cents` 另给 `<p>_yuan`），其余按状态（401/403/429/5xx），最后 "操作失败：<原文>"。后台用 `lib/admin-errors.ts` 的 `adminErrorText(err, context?)`：先查 `ADMIN_CODES`（中文直写，只在后台包），再回落到 `errorText`（中文）；带 `context` 时为"<context>：<详情>"（不会出现双前缀）；`adminMessageText` 翻译库里存的无码英文（如订单 `fulfil_error`）。`scripts/check-error-codes.mjs`（`make check`、CI spa job）：`../src/error_codes.txt` 里的每个码都必须有映射（门户命名空间必须在 `CODE_KEYS`），多余/重复映射也失败。新增服务端错误 → 加码（Rust 宏）→ 登记 → 在这里加映射。
- W21 共用组件：`components/dialog.tsx`（原生 `<dialog>` + `showModal`：焦点陷阱/Esc/背景惰性，无库、CSP 安全；jsdom 无 showModal 时退化为 `open` 属性）、`components/confirm-dialog.tsx`（`ConfirmProvider` + `useConfirm()` → `Promise<boolean>`，替代 `window.confirm`（手机上英文 OK/Cancel）；`destructive` 红色按钮；后台在根部挂 Provider；无 Provider 时退回 `window.confirm`，所以单页测试照旧用 spy 应答；门户可给 Provider 传翻译后的默认按钮文字）、`components/row-menu.tsx`（表格行「⋯」菜单，`role=menu`，键盘：↓ 打开、方向键/Home/End、Esc 回到按钮；`fixed` 定位不被表格滚动容器裁切）、`components/tabs.tsx`（WAI-ARIA tablist，方向键切换）、`components/ui/table.tsx` 的 `ScrollFade`（横向滚动容器，两侧渐隐提示还有内容；`Table label=` 时是可聚焦的具名 region）；`Badge` 不换行、success 用 emerald-700（对比度 5.5:1）；`TableHead` 不换行。`lib/datetime.ts`：后台唯一的日期格式（zh-CN、24 小时、**北京时间 Asia/Shanghai**，与浏览器语言/时区无关）：`fmtDateTime`/`fmtDate`/`fmtTime`/`fmtDuration`；日期输入 = 北京日（`dateInputValue`，提交 `endOfDayIso` = 当天 23:59:59 +08:00），`datetime-local` 同样按北京时间（`datetimeInputValue`/`datetimeInputIso`）；标签写「（北京时间）」（`TZ_LABEL`）。服务端存 UTC。
- `src/lib/qr.ts` + `src/components/qr-code.tsx` — 本地 QR 编码器（字节模式、1–40 版、M 级纠错、自动选掩码）渲染为内联 SVG：订阅链接与支付二维码都不出浏览器、无 CDN、符合 CSP。测试用独立解码器 jsQR（仅 devDependency）往返验证。

## i18n（R18）

- 前台（登录、用户门户、购买等面向用户的页面）中英双语；**管理后台只做中文**（直接写中文，`admin-app.tsx` 用 `<FixedLocale locale="zh">` 包住整个后台，共享卡片如改密码随之显示中文）。
- API：`import { useT, useLocale, setLocale, LocaleSwitch, FixedLocale } from "../i18n"`；`const t = useT(); t("login.title"); t("portal.expires", { date })`。语言 = localStorage `akari.locale`（读写都 try/catch）→ 否则浏览器语言（zh* → zh，其余 en）。每个界面挂 `useHtmlLang(locale)` 同步 `<html lang>`（zh-CN / en）。
- 字典：`src/i18n/zh.ts` 是键的正本，`src/i18n/en.ts` 类型为 `Messages`（= zh 的形状），**缺键/多键都是编译错误**；`i18n.test.tsx` 另断言两边键与 `{占位符}` 一致。
- **新增功能的约定（W3 购买页等照此执行）**：在 `zh.ts` 与 `en.ts` 各加一个**顶层命名空间**（如 `purchase: { title: "...", ... }`），键用 camelCase，插值写 `{name}`；页面里用 `t("purchase.title")`。不要在运行时按需导入或注册字典，不要在组件里写面向用户的硬编码文案（管理后台除外）。服务端错误用 `errorText(err, t)`；新的服务端错误码在 `errors` 命名空间加键并登记到 `lib/errors.ts` 的 `CODE_KEYS`（见上「errors.ts」）。日期用 `toLocaleDateString(locale === "zh" ? "zh-CN" : "en")`。

## 规则

- REST 请求走 `lib/api.ts` 的 `get/post/put/patch/del`，它们固定拼 `apiBase`（= `/{prefix}/api/v1`）。
  **后端 `/auth/*` 不在 `/api/v1` 下**：登录/登出只能用 `login()`/`logout()`（拼 `authBase` = `/{prefix}/auth`，由 `prefixBase`（路径第一段）推导）。
  守卫：`scripts/check-auth-paths.mjs`（`make check` 与 smoke 都会跑）+ smoke 对打包 JS 的 grep。登出失败必须可见；成功后 `lib/session.ts` 的 `resetAfterLogout()`（`clear()` 不通知观察者，界面会停在仪表盘）。Node >= 22.18。
- Vite 产出的资源：门户以 `/assets/`、后台以 `/admin/assets/` 开头（`vite.config.ts` 的 `base`；spa.rs 靠这个做前缀改写）；不要改 `base`。**动态 `import()`（W21，仅后台）**：分块之间用相对路径互相导入，按导入方模块的 URL 解析，所以保留秘密前缀；Vite 的预加载助手会用 `base` 绝对路径（`/admin/assets/…`，丢前缀）去取依赖，因此 `modulePreload: false` + `cssCodeSplit: false` 让依赖表恒为空，`check-bundles.mjs` 对非空依赖表或绝对路径的动态导入失败。门户仍是单一分块。
- CSP 为 `default-src 'self'; style-src 'self' 'unsafe-inline'`：禁止内联脚本和外部 CDN（二维码、下载都在本地生成）。
